# 제출용 시연 대본

시연 앱: https://nexora-n28m.axhub.app/workspace/demo . AXHub 로그인 후 Guided Demo를 연다. 모든 버튼은 서버의 실제 규칙과 PostgreSQL 저장을 호출한다. 화면의 합성 표식과 규칙 기반 설명 표식을 가리지 않는다. 이번 배포·브라우저 검증 결과는 별도 증거를 확인한다.

## 도입 — 운영 원본

통제 현황에서 원본 거래처50개·240건·232,865,386원을 보여준다. 거래처 관계 분석에서 D-011과 D-024, D-011과 D-037의 직접 간선 및 세 거래처의 전이 그룹을 설명한다. 현재 마스터로 과거를 재검산한 결과이며 부정 확정이 아님을 밝힌다. 운영 원본을 정정하거나 지급하지 않는다.

## A — 정상 지급

1. Guided Demo에서 A 새로 시작. 별도 실행이 생성되고 운영 자료는 보존된다.
2. 다음 단계: 합성120만원 요청 접수.
3. 다음 단계: 규칙 기반 설명. 외부 LLM 결과가 아니며 지원 승인 대상과 부족 증빙을 표시한다.
4. 다음 단계: 영업팀 합성 증빙 제출 및 별도 지원 검토, 상신.
5. 다음 단계: 별도 모의 영업지원 승인. 승인 완료 후 재무 작업 생성.
6. 다음 단계: 2026-07-03 모의 지급 일정 반영.
7. 다음 단계: 모의 지급·영수증·감사, 재무 작업 완료. 실제 은행 송금은 없다.

## B — 계좌 변경과 Decision Replay

1. B 새로 시작, 기존120만원 요청→증빙·상신→지원 승인→일정 반영까지 단계별 실행.
2. 계좌 정정 단계 실행. 별도 거래처 B가 대표자·등록계좌 두 조건으로 연결된다.
3. Decision Replay 전후:120만원·지원 전결·일정 반영 →230만원·임원 승인 필요·기존 심사 대체. 원래 일정 중지·새 심사 및 영업/재무/내부감시 작업을 확인한다.
4. 그룹 증빙 재검토→지원 재승인. 여기서는 임원 대기로 남는다.
5. 임원 모의 승인 후 최종 승인 완료. 최초 지원 승인으로 임원 권한을 우회하지 않는다.

## C — 부족 정보와 거절

1. C 새로 시작→요청 접수→증빙 부족 보류. 지급이 없고 영업 확인 작업이 생성된다.
2. 부족 정보 설명→합성 회신·검토. 영업 작업 완료 결과 확인.
3. 재상신→별도 모의 승인자가 거절. 거절 상태와 새로운 보완 작업, 지급0건 확인.

## 마무리

새로고침해 마지막 실행이 복원되는지 확인한다. 새로 시작은 다른 실행을 생성할 뿐 기존 감사 기록을 지우지 않는다. 현재 실제 모델 호출은 키 부재로 미검증이며 규칙 기반 설명과 분리한다. 최종 제출 화면과 영상 파일 업로드는 별도 접수 단계다.
