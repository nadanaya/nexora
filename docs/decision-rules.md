# 결정 규칙과 상태
규칙 버전은 backend/domain.py의 RULES가 기준이다. 금액은 정수 원 단위, AI 출력에서 계산하지 않는다.
1. 빈 값·NONE은 일치하지 않는다. 두 개 이상 직접 일치 → 간선, connected_components → 전이 그룹. 전이 연결을 직접 일치로 설명하지 않는다.
2. 원본 월 합계와 실제 운영 노출액을 구분한다. 성공 지급·활성 요청을 같은 원본 항목으로 중복 집계하지 않는다. 원본 반려·미지급과 현재 운영 심사를 구분한다.
3. 월 노출액 <=2,000,000원: 영업지원. >2,000,000원: 영업지원 절차 후 영업임원 최종 승인.
4. 기안자 본인 승인 금지. 승인·증빙 검토·지급은 서버 역할과 회차·문맥 해시 재검증.
5. 필수 증빙 및 실제 지급 수취계좌 검증 없으면 ON_HOLD와 영업 작업 생성. 입금계좌를 복사해 증빙 완료로 처리하지 않는다.
6. 승인 취소·정보/금액/관계 변경은 승인 무효화와 일정 중지. 합병/분리는 대체 심사 생성. 거절은 후속 작업과 일정 취소. 기지급은 삭제·재지급하지 않고 사후 조사.
7. 유효한 승인·증빙·재무 일정이 있는 경우만 모의 지급. 멱등 키와 DB 지급 항목 유일성으로 재시도·동시 요청 방어.
8. 상태·성공 지급·감사는 동일 거래로 저장. 감사는 해시 연결·DB 변경 금지 트리거 사용.
AI에는 실행 권한이 없다. 설명 오류·형식 오류·미확인 근거는 실패 감사만 남기고 업무 판단을 유지한다.
실제 상태 이름·전이·예외 코드는 backend/domain.py 및 ../backend/openapi.json, 회귀 증거는 test-results.md 참조.
