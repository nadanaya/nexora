# 제출용 시연 순서

## 환경과 자료 구분

운영 주소는 기존 NEXORA 앱입니다. 원본 50개 거래처의 검산·관계 결과는 운영 화면에서 확인합니다. 지급·취소·관계 정정을 반복하는 자동 시연은 `python scripts/demo-server.py`로 시작한 `http://127.0.0.1:3107`에서 진행합니다. 이 환경은 독립 PostgreSQL과 합성 거래처 10개, 합성 역할을 사용합니다. 원본이나 운영 상태를 초기화하지 않습니다.

`/__demo/actor/draft`, `/support`, `/sales`, `/executive`, `/finance`는 로컬 검증 실행기에서만 제공하는 합성 역할 전환 경로입니다. 운영 앱의 인증 우회 경로가 아니며 실제 사람의 승인을 증명하지 않습니다.

## 먼저 보여줄 것

1. 원본 거래처 50개·장려금 240건·232,865,386원과 원본 해시 보존 증거를 설명합니다.
2. D-011—D-024의 대표자·주소, D-011—D-037의 대표자·등록계좌 직접 연결을 보여줍니다. D-024와 D-037 사이에 직접 간선을 그리지 않습니다.
3. 6월 그룹 합계 3,888,097원으로 영업임원 최종 승인이 필요함을 설명합니다. 회수계좌와 지급 수취계좌를 구분하고, 관계 정황을 부정 확정으로 말하지 않습니다.

## A 정상 업무 흐름

1. draft 역할로 WEB-N1 / 2026-06 심사를 기안합니다. 2,000,000원 경계이므로 영업지원 전결 대상입니다.
2. AI 분석을 요청합니다. 현재 설정에서는 미설정 오류가 나고 상태가 유지됩니다. 실제 AI 키가 준비되면 이 단계에서 관계 근거·위험·부족 증빙·작업 제안 JSON을 보여줍니다.
3. `python scripts/demo-api.py prepare WEB-N1`로 sales 역할이 합성 정산·계좌 증빙을 제출하고 support 역할이 검토한 결과를 보여줍니다.
4. draft가 상신합니다. 같은 계정의 사람 승인 버튼이 비활성화됨을 확인합니다.
5. support 역할로 전환하여 심사를 선택하고 근거를 입력해 승인합니다.
6. finance 역할로 전환하여 2026-07-03 지급 일정을 반영하고 모의 지급을 실행합니다.
7. 모의 지급 완료 상태·일정 상태·영수증과 감사 이벤트를 보여줍니다. 실제 은행 이체는 없습니다.

## B 조건 변경

1. draft로 WEB-C1 심사를 기안하면 WEB-C1/C2/C3의 합계는 2,400,000원이고 영업임원 최종 승인이 필요합니다.
2. `python scripts/demo-api.py approve-schedule WEB-C1`로 합성 증빙·별도 지원 승인·임원 승인·재무 일정을 준비합니다.
3. 관계·영향 화면에서 WEB-C1의 대표자를 합성 값으로 정정하는 미리보기를 실행합니다. 자료 구분은 합성 시나리오, 적용일은 가상 기준일입니다.
4. 2,400,000원→900,000원, 승인 무효화·일정 중지를 확인한 후 정정을 적용합니다.
5. 기존 심사가 대체되고 그룹별 새 기안이 생기는 것을 보여줍니다. 이전 일정은 중지 상태입니다.
6. `prepare WEB-C1` 후 새 심사를 상신합니다. 900,000원으로 영업지원 승인 대상이 되었으며 이전 승인을 재사용하지 않는 것을 확인합니다.

## C 정보 부족·승인 거절

1. WEB-H1을 증빙 없이 상신합니다. 보류와 지급 차단 사유, 영업 확인 작업이 생성됩니다.
2. `python scripts/demo-api.py prepare WEB-H1`로 합성 회신을 제출·검토합니다. 실제 확보 증거라고 표시하지 않습니다.
3. `python scripts/demo-api.py close-sales WEB-H1`로 검토 완료된 영업 작업을 완료하고, draft가 재상신합니다.
4. support가 거절 근거를 입력하고 거절합니다. 거절 상태와 새 보완 작업, 지급·일정 미생성을 확인합니다.
5. 이미 존재하는 일정의 취소·정정·거절 전환은 자동 테스트의 SUSPENDED/CANCELLED 증거를 함께 보여줍니다.

## 종료·재현

`python scripts/demo-api.py snapshot`으로 상태·작업·지급·감사와 DB 행 수를 저장합니다. `stop`으로 이번 로컬 서버·임시 DB만 종료합니다. 새 서버는 별도 임시 클러스터로 시작하므로 같은 시나리오를 다시 실행할 수 있습니다. 중단한 동일 합성 DB를 이어갈 때는 실행기가 출력·사용한 OS 임시 폴더에 한해 `demo-server.py --resume <폴더>`를 사용합니다.

실제 HTTP 자동 시연 전체는 `python scripts/demo-api.py all`입니다. API- 접두사 거래처를 사용하므로 WEB- 브라우저 시연과 충돌하지 않습니다. 최초 실패와 수정 후 결과를 모두 보관하며 실제 AI 미연결을 숨기지 않습니다.
